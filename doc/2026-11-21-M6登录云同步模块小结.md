# M6 安卓端登录 + 云同步模块小结（2026-11-21）

## 用户的问题
按实施计划完成安卓端：账号密码登录/注册（预留手机号验证码结构）、云同步（push→pull→LWW 合并），打通与 M5 后端的端到端闭环，并在 MuMu 上跑 E2E。

## 如何分析的
- 网络栈：Retrofit 2.11 + OkHttp 4.12 + kotlinx-serialization 转换器（不引入 Gson/Moshi，与项目 JSON 栈一致）；baseUrl 存 SharedPreferences，默认 `http://10.0.2.2:8080/`（模拟器回环宿主机），登录页可改。
- 同步策略（与后端约定）：固定顺序 **push(dirty 账单 + 全量账户/预算) → pull(since=lastSyncAt) → LWW 合并 → dirty 清零 → 记 serverTime 水位**；远端 updatedAt 严格大于本地才覆盖。
- 删除传播：把 `TxDao.delete/clear` 改成**软删（墓碑 deleted=1, dirty=1）**，否则 pull 会把删掉的账单复活；`replaceAll`（恢复备份）也先软清空再覆盖。
- 实体即 DTO：三个 Room Entity 加 `@Serializable` 直接与后端 user_tx/account/budget 对齐，省去双份映射。
- 明文 HTTP：Manifest 加 `usesCleartextTraffic="true"`（头号集成坑，按计划处理）。

## 如何解决的（踩坑记录）
1. **转换器包名**：`com.jakewharton.retrofit.converter...` 实际是 `com.jakewharton.retrofit2.converter...`（查 jar 内容确认）。
2. **encodeDefaults 大坑**：kotlinx 默认不序列化等于默认值的字段 → `accountId="acc_cash"` 没上送 → 后端 `account_id cannot be null` 500。双端修复：客户端 `Json { encodeDefaults = true }` + 服务端实体字段默认值兜底。
3. **退出登录卡片不刷新**：登录态不是响应式状态 → 加 `authVersion` 计数触发重组。
4. **测试脚本**：Toast 在 Android 12+ 不进 uiautomator 树；MuMu screencap 偶发返回旧帧 → 断言改用 logcat（OkHttp FAILED）+ "上次同步"时间不变 + dump 文本，多帧截图仅作辅助。
