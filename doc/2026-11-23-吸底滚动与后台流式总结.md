# 吸底滚动与后台流式生成总结（2026-11-23）

## 用户的问题
在 AI 回复页面实现两块功能：
1. **智能吸底滚动（stick-to-bottom）**，6 条规则：isAtBottom 贴底判定（距离阈值 50~80px）；贴底时流式内容自动跟随滚动；用户上翻时绝不打断（用户优先级最高）；「回到底部 ↓」悬浮按钮点击平滑回底并隐藏；发送消息强制平滑滚底、流式过程用即时滚动避免动画排队；滚动监听防抖/节流不逐帧强制 layout。
2. **后台流式生成与返回恢复**，6 条规则：生成任务归属服务端（断开不取消）；前端全局流管理器与视图解耦（按 sessionId/messageId 持有缓冲/状态/订阅）；切走时退订但连接与缓冲继续；切回时立即渲染已有缓冲继续追加；断线/杀进程后凭 messageId+offset 断点续传（任务已完成直接拉完整消息）；多端一致。
- **范围确认（AskUserQuestion）**：用户明确"不做多端一致，记录还是放在本地存储"——多端同步（规则6）砍掉，规则1~5 + 吸底滚动全做。

## 如何分析的
1. **现状摸底**：服务端零会话/消息存储，`POST /api/ai/chat/stream` 是跟 HTTP 连接同生共死的同步流（断开即丢结果）；客户端流式跑在 `ChatScreen` 的 `rememberCoroutineScope` 里（切 tab/切会话组件销毁即取消）。两者都违反目标规则。
2. **架构设计**：
   - **服务端任务化**：`AiTaskService` 内存任务表（messageId → 缓冲/act/状态），`POST /chat/task` 立即返回 messageId 并在**线程池**执行生成（与连接解耦，规则1）；`GET /chat/stream/{id}?offset=N` 以 **SSE** 输出——先按 offset 补发缺失正文（断点续传，规则5），任务还在生成则 wait/notify 挂起推送增量，已完成则补发后直接发 `done` 关闭；写失败仅断本连接、生成继续；20s 心跳 ping；完成任务保留 30 分钟、过期返回 `expired` 事件。
   - **客户端全局管理器**：`ChatStreamManager`（App 级 object + SupervisorJob/IO scope），按 messageId 持有 StateFlow 快照（缓冲/状态/act/allowAct/persisted/序号），**独立于组件生命周期**（规则2/3）；SSE 按行解析 `event: act|delta|done|expired`，断线指数退避重连（offset=已收长度，规则5）；pending 集合持久化到 SharedPreferences（messageId|convId|allowAct），杀进程重启 `resumePending` 以 offset=0 拉完整消息（规则5）；**落库以 messageId 为主键幂等**（先落库→清 pending→发布终态，任意时刻杀进程不丢不重）；pruneFinished 裁剪已落库终态快照防膨胀。
   - **吸底滚动**：isAtBottom 状态 + 贴底判定（末项底边距视口底边 ≤ 72dp）；**只在滚动停止瞬间评估**（snapshotFlow 监听 isScrollInProgress，防抖且避免内容增长把跟随中的用户误判为上翻）；100ms 节流轮询跟随（贴底才滚、手势/动画中绝不打断）；FAB「回到底部」；发送时强制平滑滚（animateScrollToBottom）、流式用即时滚（scrollToBottom，先等两帧布局再定位+补滚超出部分）。
   - **ChatScreen 重构**：busy 派生自 `startPending || 当前会话有 STREAMING 任务`；`LaunchedEffect(convId)` 统一"加载 Room → 订阅 StateFlow（replay 立即渲染已有缓冲，规则4）→ 消费 act（幂等，按任务所属会话执行）"；切会话只改 convId（订阅随 effect 重启自动退订/重订，规则3）；首轮回复由管理器以 messageId 落库，`runQueryThenReply` 只补 `[系统]` 结果（避免重复入库），二轮 `allowAct=false` 不递归。
   - **打字机兼容**：气泡初始化改为"空缓冲新任务从 0 逐字流出；已有缓冲（切回/历史）立即全文渲染"（规则4"立即渲染已有缓冲"）。

## 如何解决的（踩坑记录）
1. **Docker 引擎反复假活**：READY 后构建即 `ENGINE_DIED` → 轮询改为**连续三次** `docker info` 成功才认为稳定（t=300s），构建前再复查一次。
2. **Clash 8888 掉线致服务端镜像构建失败**（Docker 拉 `eclipse-temurin:21-jre` 走代理被拒）→ 重启 Clash Verge 等 5s 就绪后重建成功。
3. **PowerShell 不支持 `VAR=val cmd` 语法**（`MSYS_NO_PATHCONV=1 docker ...` 直接报错）→ 改 `$env:MSYS_NO_PATHCONV='1'`。
4. **Kotlin 局部函数必须先声明后用**：`runQueryThenReply` 引用声明在其后的 `monthContext()` 编译失败（Unresolved reference）→ 调整声明顺序。
5. **.NET 文件 IO 不认 PowerShell 的 `cd`**（当前目录仍是工作区根）→ 压缩镜像用绝对路径。
6. **adb 每条命令前必须重新 connect**（daemon 每次被杀）；`foreach{} | Select-Object` 是 PowerShell 语法错误（先收集到数组再管道）；adb `input text` 用 `%s` 表示空格。
7. **Kotlin 字符串模板 `$text.length`** 不会解析 `.length`（输出 text 值+字面量".length"）——排查中据此确认了 resume 消息实际内容长度。
8. **SSE 空行丢换行 bug**：客户端用 `data.isNotEmpty()` 判断拼接，delta 首行为空串会丢前导换行 → 改用独立 `hasData` 标志。
9. **服务端 wait 醒来用旧值**：`task.wait()` 后未重取缓冲会多空转一轮 → 内层 while 就地重取，超时无数据才发 ping。
10. **Activity 泄漏**：读取协程长生命周期，管理器统一用 `applicationContext`。
