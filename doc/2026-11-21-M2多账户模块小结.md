# M2 多账户模块小结（2026-11-21）

## 用户的问题
按实施计划执行 M2：多账户（微信/支付宝/现金/银行卡）+ 账户间转账，同时修复 `Ledger.summary` 把非支出算进收入的既有 bug，完成后在 MuMu 上跑端到端测试。

## 如何分析的
- 转账表达：不建独立表，用 `Tx.type="transfer"` + `accountId`(转出) + `toAccountId`(转入)，明细流里可直接看到转账条目，实现成本最低。
- 迁移设计：DB v1→v2（`MIGRATION_1_2`）建 accounts 表 + `ALTER TABLE txs` 加两列（带默认值，且 Entity 用 `@ColumnInfo(defaultValue=...)` 声明保持 Room schema 校验一致）+ SQL 插入 4 条固定 ID 默认账户；全新安装不走迁移，靠 `AccountStore` 检测 `count()==0` 补种。
- 旧数据归属：迁移时存量账单 `accountId` 默认落 `acc_cash`（现金），与默认账户一致。
- 统计口径：`summary()` 改为 `when(type)` 显式分支（transfer 两侧都不计）；`categoryBreakdown/insights/weekDaily` 本就显式过滤 expense，只需改这一处。
- 余额公式（纯函数 `Ledger.accountBalance`）：初始余额 + 收入进账 − 支出付款 ± 转账。

## 如何解决的
1. 数据层：`AccountEntity/AccountDao/Migrations`，`AppDatabase` 升 v2；`TxEntity` 加 `accountId/toAccountId`；`Tx` 领域模型同步加字段（带默认值，旧 JSON 备份可反序列化）。
2. `AccountStore`（与 TxStore 同模式：Room + Flow 回写 StateList），`AppStore` 挂载。
3. UI：MainActivity 加第 5 个「账户」tab；`AccountsScreen`（总资产卡、账户卡片含余额与本月收支、转账按钮、账户增删改对话框、设默认/删除保护默认账户）；`RecordSheet` 支出/收入/转账三段切换 + `AccountPicker` 账户 chips（转账时显示转出/转入两行、隐藏分类、校验两账户不能相同、商户自动填"转账"）；`TxRow` 明细行显示"分类 · 账户"，转账行显示"现金 → 微信"和"→¥100.00"。
4. 修复过程中发现并解决：`AccountsScreen` 的"+ 新增账户"Row 误写在 Column 外导致浮层重叠，已移回滚动容器内。
