# 记账 App UI 大改设计研究总结（2026-11-21）

## 用户的问题
对 Kotlin + Jetpack Compose + Material 3 的安卓记账 App 做 UI 大改，原则：砍掉标语/提示/次要标签让布局自解释；错误提示人性化（不出现"返回400"等技术术语）；同时提升 UX / DX / AX。只做研究不写代码，输出四部分中文要点（≤1200字），每条结论注明出处。

## 如何分析的
通过网络检索分四路并行取证：
1. Material Design 3 / Android 官方文档：表单 error state、empty state、导航与设置页准则；
2. 记账类 App（Ivy Wallet、Actual Budget、Budgetum 等）及登录/流水/统计/空状态的界面模式；
3. HTTP 状态码 → 人性文案的映射实践与表单校验时机研究（NN/g、Luke Wroblewski）；
4. Agent Experience（AX）：无障碍语义、稳定布局、选择器稳定性相关论文与文章。
每条结论取 P0/P1 来源（官方文档、NN/g、arXiv）优先，交叉验证后压缩为一句话要点。

## 如何解决的（核心结论）
1. **M3 官方**：错误文字放在字段下方并替换辅助文字（避免布局跳动），文案写"如何避免"而非描述错误（m3.material.io）；空状态 = 插图 + 一句正向 tagline + 单一行动按钮，说明缺数据原因与解法（m2.material.io、Carbon、Android Developers）；底部导航限 3–5 个目的地，设置用分组列表、子页标题与入口标签一致（m3.material.io、developer.android.com）。
2. **记账 App 模式**：注册只留用户名+密码、无确认密码、无说明文案（sensecentral、superdesign）；登录字段上方可见标签 + 密码切换 + 错误就地保留输入（convertica）；流水一行 = 左分类图标+名称、右带符号彩色金额、按日期分组（budgetum、GitHub UI 改版文档）；统计页靠直接数值标注与顺序色板，颜色不单独承载信息（Section508、WCAG 1.4.1）。
3. **人性化错误映射**：400/422→字段下方具体原因；401→"登录已过期"并保留草稿；404/409→"内容不存在或已被修改"；429→"操作太频繁"；5xx→"服务出了点问题，请稍后重试"+重试按钮；一律不展示状态码（adamarant、fixmymess、makerhunt）。校验时机：离字段就地校验 + 提交时统一复查，焦点移至首个错误；认证错误笼统防枚举，格式错误要具体（NN/g、sensecentral）。
4. **AX**：无障碍语义即 AX（读屏与 agent 共用 accessible name/角色，cyberdunes）；Compose 中 Icon/Image 提供准确 contentDescription、装饰设 null、状态用 stateDescription（developer.android.com）；布局与控件位置跨页稳定一致以减少 agent 反复定位（arXiv 2605.02729）；每个主操作有稳定可访问名/选择器（brainy.ink）。

## 最后结果如何
已按用户要求输出四部分、每条一句话带站点出处的要点式研究结论（见聊天回复），并落盘本总结文档至 doc/ 目录。未写任何代码；来源均为公开网页，无编造数据。
