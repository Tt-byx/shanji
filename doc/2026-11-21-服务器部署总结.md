# 服务器部署总结（2026-11-21）

## 用户的问题
用户提供 SSH 密钥（本地 `.pem` 文件，路径已隐去）与公网 IP（`x.x.x.x`，已隐去），要求：① 清除服务器上已确认无用的旧进程（java、mq、mysql）并删除；② 把 shanji-server 后端部署到该服务器；③ 安卓端登录后端地址切到该服务器并测试连接正常。

## 如何分析的
1. **摸底**：SSH 连接（密钥权限需 `icacls /inheritance:r + grant` 修复，Windows OpenSSH 要求私钥仅当前用户可读）；确认服务器为阿里云 Alibaba Cloud Linux 4、Docker 26.1.3、内存仅 891Mi。
2. **识别清理对象**：`chat-server.service`（java，占 8080，正是我们要的端口）、rabbitmq（docker 容器 + 宿主残留进程）、`chat-mysql` 容器；**`ecs_mq.service` 是阿里云网卡多队列调优脚本（非消息队列），保留不动**。
3. **部署方案选型**：服务器拉不动 Docker Hub（retry）→ 不在服务器 build；改用本地镜像 `docker save → gzip → scp → docker load`（163MB 传输）；MySQL 复用服务器已有 `mysql:8.0` 镜像（override 文件指定），避免传 1.12GB 的 8.4。
4. **内存约束**：891Mi 要跑 MySQL + Spring Boot → override 加 `JAVA_TOOL_OPTIONS=-Xmx256m`。

## 如何解决的（踩坑记录）
1. **pkill -f 自杀**：`pkill -f '/opt/rabbitmq/...'` 匹配到 ssh 远程 shell 自身命令行导致会话中断 → 改 `pkill -x beam.smp`（精确进程名）。
2. **PowerShell 管道破坏二进制**：`docker save | gzip` 走 PS 管道损坏数据 → 改为 `docker save -o` 落盘 + GZipStream 压缩 + scp。
3. **compose 项目名不一致**：本地目录 shanji-server vs 服务器 /opt/shanji → 镜像名 `shanji-app` 对不上 → `docker tag shanji-server-app:latest shanji-app:latest`。
4. **服务器缺 Dockerfile**：`up` 触发 build 失败 → `up -d --no-build` 用现成镜像。
5. **安全收窄**：数据库端口从 `0.0.0.0:3306` 改 `.env` 为 `127.0.0.1:3306`（仅本机），App 8080 对外（安全组已放行）。

**清理明细**（用户确认无用）：chat-server 服务（stop+disable+删 unit）、rabbitmq 容器与宿主进程、chat-mysql 容器（-v 删卷）、`/opt/chat-server`、`/opt/jre17`、`/opt/mysql`、`/opt/install-server.sh`、rabbitmq/erlang 相关目录；清理后无残留进程、8080/3306/5672 全释放、docker 无容器。

**部署明细**：`/opt/shanji/`（compose + .env + override）；容器 `shanji-app`(0.0.0.0:8080) + `shanji-db`(127.0.0.1:3306, mysql:8.0, healthcheck)；两容器均设 `restart: always`（服务器重启自动拉起，已验证）。
