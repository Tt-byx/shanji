# 2026-11-22 AI 聊天流式输出、记忆与对话管理总结

## 用户的问题

AI 聊天功能做了之后提了三个改进：
1. 手机上键盘输入时，输入框没有弹到键盘上面（被遮挡）；
2. AI 回复要流式输出，不要一下子蹦出一大段话；
3. 要记忆功能和聊天对话管理，参考 `C:\Users\28182\Desktop\Agent` 项目的实现。

## 如何分析的

1. **参考项目调研**（Explore 子代理）：Agent 项目的记忆分层是——`conversation` 表（id/title/summary/软删）+ `chat_message` 表（role/content 按 conversation 关联）+ **滑动窗口短期记忆**（最近 N 轮）+ **溢出摘要长期记忆**（消息超出窗口时，旧摘要+被挤出的消息经 AI 压缩成新摘要存 `conversation_summary`，Redis 只是热缓存、MySQL 是持久底座）。会话管理是列表（按更新时间倒序）/删除（软删 status=0）/重命名（改 title）。
2. **映射到闪记**：闪记是单机 App，无需 Redis/MySQL 分层——本地 Room 即持久底座；摘要存 Room 的 `conversations.summary`；滑窗+摘要逻辑本地实现，摘要生成复用现有 GLM 中转通道。
3. **流式方案选型**：后端新增 `POST /api/ai/chat/stream`（chunked text/plain），透传 DeepSeek 的 SSE delta；动作（queryTx/addTx）用 `#ACT#JSON` 首行协议——服务端识别后吞掉该行走独立回调，客户端解析执行，正文继续流式，两者互不干扰。
4. **键盘问题根因**：ChatScreen 根布局没消费 IME insets；修复 = 根 Column 加 `Modifier.imePadding()`（Manifest 已是 `adjustResize`，二者配合生效）。

## 如何解决的

### 后端 shanji-server
- `AiService.chatStream(req, onDelta, onAct)`：RestClient `stream:true` 调 DeepSeek，BufferedReader 逐行读 SSE，delta 里 `&#10;` 还原为换行；首行缓冲判断是否 `#ACT#` 动作行（超 4096 字符无换行判定为正文放行）；信号量 2 并发照旧。
- `AiController.chatStream`：**同步写 `HttpServletResponse`**——最初用 `StreamingResponseBody` 触发 async dispatch，Spring Security 的 ThreadLocal 上下文在异步线程丢失导致 403，改同步后修复（已记入代码注释）。
- CHAT_SYSTEM 改为 `#ACT#` 首行协议；非流式 `/chat` 兼容解析该协议 + 旧 JSON 协议兜底。

### 安卓 shanji-android
- **Room v5**（`MIGRATION_4_5`）：新增 `conversations`（id/title/summary/createdAt/updatedAt/deleted）与 `chat_messages`（id/conversationId/role/content/createdAt，索引 conversationId）。
- **`data/ChatStore.kt`**（记忆核心，参考 Agent 的 ConversationHistoryStore）：
  - 滑窗：`buildMemory` 只取最近 `WINDOW=20` 条发给 AI；
  - 溢出摘要：消息超 `SUMMARIZE_AT=40` 条时，最旧一半+旧摘要经 AI 压成新摘要存 `summary`，删除已压缩原始消息（失败不阻塞聊天）；
  - 对话管理：latestOrCreate/new/list/rename/softDelete/首条消息自动标题。
- **`AiClient.chatStream`**：OkHttp ResponseBody 逐行读，`#ACT#` 行走 `onAct`，正文走 `onDelta`（调用方 post 回主线程改 Compose 状态）。
- **`ChatScreen` 重写**：
  - 根 Column `imePadding()` 修键盘遮挡；
  - 流式渲染：气泡空文本时显示 `▌` 光标占位，delta 累积实时刷新；
  - 会话管理 UI：顶栏「历史对话」（列表+改名+删除）与「新对话」按钮；
  - 记忆持久化：消息全量入 Room，发送时 `buildMemory` 组装摘要+滑窗；
  - `cleanText`：显示/入库/加载三处统一还原 `&#10;`（服务端 chunk 可能切断实体）。

**过程中的坑**：
- `StreamingResponseBody` 异步 dispatch 丢 Spring Security 上下文 → 403（改同步写 HttpServletResponse）；
- DeepSeek 把换行转成字面 `&#10;` 且可能跨 chunk，服务端单 chunk 替换不彻底 → 客户端对累积全文三处统一清洗；
- uiautomator dump 里 `&#10;` 是 XML 对真实换行的转义，别误判为脏数据；
- **键盘避让在模拟器无法直接验证**（MuMu 软键盘不实际渲染窗口、用物理键盘映射），`imePadding` + `adjustResize` 是标准方案，需真机实测；
- 本机 curl SSL 报 `CRYPT_E_REVOCATION_OFFLINE` 是 Windows schannel 吊销检查离线，非网络故障；容器内 Maven 必须走宿主 Clash 代理（`maven-proxy-settings.xml`，host.docker.internal:8888），Clash 被杀会导致编译失败。

**遗留**：键盘避让待真机验证；旧消息里的 `&#10;` 在加载时已自动清洗，无需迁移。
