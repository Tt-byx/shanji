# 流式打字机、AI 免登录与服务器地址总结（2026-11-22）

## 用户的问题
1. **流式输出还是不行**：真机上 AI 回复仍是一下子蹦出一大段；要求参考 DeepSeek 客户端的设计、逆向看看它怎么设置的，愿意为了流式把显示改成和 DeepSeek 一样；
2. **登录要自己填服务器地址**：默认地址不是自己的服务器，希望默认就是自己的服务器，且不让用户可见和修改；
3. **不登录也能用所有功能**：除了同步，其它（AI 问答/记账/洞察等）都不该要求登录。

## 如何分析的
1. **流式根因（服务器逐块计时实测）**：对 `/api/ai/chat/stream` 用 curl `--trace-time` 抓时间线——**87 个 chunk、每 ~10ms 一块、整段200字回复0.89 秒全部传完**。结论：服务端 chunked 流式完全正常，客户端按 chunk 读也正常，真正的根因是 **`deepseek-flash` 模型太快 + 回答太短**——不到1秒就生成完，任何客户端看起来都是一次性蹦出。DeepSeek 官方 App 配的是较慢的 V3/推理模型，天然有"打字感"。
2. **逆向调研**：本机上次的 DeepSeek APK 残留已清理；重新下载走了三条路——官网（只挂应用商店二维码）、apkpure（403）、豌豆荚（反爬54字节）——均失败；转为官方 API 文档（create-chat-completion 的 stream/SSE 规范）+ 实测计时作为依据。API 侧我们与官方一致（`stream:true` + SSE 逐段），差异只在**显示侧节奏**。
3. **服务器地址问题**：是上一轮"GitHub 公开仓库隐私脱敏"的副作用——`DEFAULT_URL` 被改成了占位 `192.168.1.100`，真机装包后默认地址不对，登录页又要手填。
4. **登录门槛**：`SecurityConfig` 是 `.anyRequest().authenticated()`，AI 四个端点全被 JWT 拦住；客户端 `AiClient.bearer()` 拿不到 token 直接抛"尚未登录"。而 AI 中转的上下文全部来自请求体，本不需要用户身份——只有云同步需要。

## 如何解决的
1. **DeepSeek 式打字机（最终方案：气泡内自带节奏）**：
   - 排查过程走了两轮弯路：先做「外部揭示协程」（launchReveal），真机日志证明它不渲染（具体死因未定位，已整体移除）；期间还发现**完成回调强刷全文会掐断节奏**；
   - 最终方案内聚到 ChatBubble 自身：`rememberUpdatedState(m.text)` + 每气泡一个 `LaunchedEffect` 循环，每 33ms 把显示长度向真实长度推进 2~5 字（≈60~150 字/秒）；历史消息初始即全文不重播动画，流式新消息从 ▌ 光标开始逐字打出；
   - 数据通路恢复为已验证的 onDelta 直接上屏（items 存全文，显示层负责节奏），无跨协程依赖。
   - **为什么要打字机**：logcat 实测 `deepseek-flash` 整段回复常以**单个931 字节 chunk 一次性到达**（服务器87-chunk 逐段实测正常，是网络合包+模型太快），直接上屏必然"一下子蹦一大段"。
2. **默认服务器地址=自己的，且不可见不可改**：
   - 新建本地文件 `shanji-android/server-url.properties`（**已 gitignore，不上传 GitHub**）写真实地址；
   - `build.gradle.kts` 构建时读取注入 `BuildConfig.SERVER_URL`（缺省回落占位地址，仓库永远不出现真实 IP）；
   - `ApiFactory.DEFAULT_URL = BuildConfig.SERVER_URL`，删掉 SharedPreferences 覆写与 `setBaseUrl`；
   - **登录页删除"服务器地址"输入框**，只留用户名/密码/测试连接。
3. **AI 免登录**：服务端 `SecurityConfig` 给 `/api/ai/**` 加 `permitAll`（同步仍需登录）；客户端 `AiClient.bearer()` 改为可选——登录了带 token，没登录不发 Authorization 头（AiApi 四个接口 header 改 `String?`，Retrofit 对 null 不发头）。
4. **部署**：Dockerfile 加本地变体 `Dockerfile.local`（注入 maven 代理 settings，不入库）→ 本地构建镜像 → save/scp → 服务器 `docker load + compose up -d --force-recreate app`。
5. **诊断日志保留**：send/chatStream 关键节点打 `SHANJI` logcat 标签（发送/入库/memory/连接/读流/onSuccess/onFailure），真机如有异常可直接 `adb logcat -s SHANJI` 取证。

## 最后结果（E2E 实测）
- **打字机 PASS**：密集采样回复文本 **387 → 527 → 692 三步渐进**（旧版为单步整段蹦出）；logcat 全链路正常（send → 入库 → memory → 连接 → 读流 → onSuccess）；
- **匿名 AI 全通**：`pm clear` 后全程未登录状态下连续完成多轮对话（含表格/加粗 Markdown 渲染截图确认）；服务器无 token 直调 `/api/ai/parse`、`/api/ai/chat/stream` 均200 正常；
- **真机地址**：`server-url.properties` 注入真实服务器，清数据冷启动即用；
- **登录页 PASS**：dump 断言无"服务器地址"字段，用户名/密码/测试连接齐全；
- **五 tab 回归 PASS**：统计/账户/我的/明细/问账本 全部正常；
- **版本**：versionCode 7 / v1.6，产物 `ShanJi-v1.6-release.apk`；服务器已部署（health UP）。
- **附带发现**：服务器/DeepSeek 偶发首字延迟（实测4.5 秒起、极端时数分钟，期间连接建立后无数据）——表现为 ▌ 等待，属上游波动，回复最终都会送达（历史消息重启后可见）；非客户端 bug。

**遗留**：① 打字机节奏（60~150字/秒）真机手感确认，觉得太快/太慢改 ChatBubble 里 `coerceIn(2, 5)` 即可；② DeepSeek 官方 APK 三渠道下载失败未能完成 bundle 级逆向，结论基于官方 API 文档 + 服务器逐块计时 + 客户端 logcat 实测；③ 本地 `server-url.properties` 与 `Dockerfile.local` 均不入库，换机器构建需重新创建（内容见本文档）；④ 上游首字延迟属服务端/模型波动，若频繁出现可考虑加"思考中"提示（DeepSeek 客户端同款）。
