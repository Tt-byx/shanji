# 2026-11-22 苹果简约风配色改造总结

## 用户的问题

整个软件的配色 UI 风格不喜欢，要简约一点的、像苹果的设计。老规矩——先去 GitHub 调研客户端 UI 设计，再动手。

## 如何分析的

### 1. GitHub 调研

用 GitHub API 检索 iOS 风格 / 记账 / 简约设计的 Compose 项目：

- **`wisnukurniawan/Compose-Expense`（185★，成熟记账 App）**：值得借鉴的不是具体色值，而是它的**分层中性色体系**——`BackgroundL1/L2 + ItemBackgroundL1/L2`（纯白背景 + #F7F7F7/#F1F1F1 浅灰项），黑色 on 色，**分层靠灰阶不靠边框**；语义色独立（Expense `#FD3C4A` / Income `#00A86B`）；
- `dimrnhhh/moneytopia`（70★）：默认紫色模板，"clean design" 无实质参考；
- 其余 iOS-style 小项目（计算器克隆等）无体系价值。

**结论**：GitHub 上没有现成的"Apple 风 Compose 主题库"可搬，权威依据回归 **Apple HIG 官方规范**（color/typography 页）。

### 2. Apple HIG 规范要点

- **语义色**：systemGroupedBackground `#F2F2F7` / systemBackground `#FFFFFF` 分组背景；label `#000` / secondaryLabel 灰；
- **强调色**：systemBlue `#007AFF` 统一用于可点/选中元素；
- **系统色**：systemRed `#FF3B30`、systemGreen `#34C759`、systemOrange `#FF9500`；
- **分割线** separator `#E5E5EA`、fill `#E9E9EB`；
- **深色**：纯黑 `#000000` 背景 + `#1C1C1E` 卡片、`#98989D` 次级文字。

### 3. 现状差距（用户不喜欢的根源）

- 紫色 `#5046E5` 泛滥：强调色、chip、选中态、分类色、图标全紫，视觉噪音大；
- 暖灰背景 `#F9F9FB` + 紫底 `surfaceVariant`（PrimarySoft 紫）导致"紫里透灰"；
- 分类色高饱和（Tailwind 系），与简约冲突。

## 如何解决的

**架构优势**：全项目颜色都从 `theme/Theme.kt` 的顶层 val 和 `Model.kt` 的 Categories 引用，硬编码仅 4 处（widget XML、状态栏、启动图标、ShareCapture 一处），所以是**低风险单点改造**：

1. **`ui/theme/Theme.kt` 全色板换 Apple 语义色**：
   - Primary → `#007AFF`（systemBlue），PrimarySoft → `#E5F1FF`；
   - Green/Amber/Red → systemGreen/systemOrange/systemRed（深色态 error `#FF453A`）；
   - Text1/2/3 → label `#000` / `#8E8E93` / `#C7C7CC`；
   - Bg → `#F2F2F7`（grouped 背景）、BorderSubtle → `#E5E5EA`（separator）、ChipGray → `#E9E9EB`；
   - **surfaceVariant 从紫底改为 fill 灰**（未选中 chip 不再透紫）；
   - 深色：`#000000` 背景 + `#1C1C1E` 卡片 + `#2C2C2E` 次级面 + `#98989D` 次级文字；
2. **`data/Model.kt` Categories 分类色** → iOS 系统色板低饱和成对浅底（餐饮橙 `#FF9500`、交通青 `#30B0C7`、购物粉 `#FF2D55`、日用靛 `#5856D6`、娱乐紫 `#AF52DE`、医疗红 `#FF3B30`、学习绿 `#34C759`、其他灰 `#8E8E93`）；
3. **杂项对齐**：`themes.xml` 状态栏 `#F2F2F7`、启动图标底色 `#007AFF`、widget（品牌字蓝、次级字 `#98989D`、底 `#FF1C1C1E`）、ShareCapture 背景 `#F2F2F7`。
