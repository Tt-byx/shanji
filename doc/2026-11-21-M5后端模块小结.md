# M5 后端模块小结（2026-11-21）

## 用户的问题
按实施计划新建 `shanji-server`：Spring Boot + MySQL + Docker Compose，账号密码注册/登录（JWT）、账单云同步接口（push/pull + LWW），并跑 curl 端到端测试。技术栈选的是用户熟练的 Java/Spring Boot + MySQL + Docker。

## 如何分析的
- 个人项目不上重方案：JWT 手签 HS256（jjwt 0.12.6）、Spring Security 无状态过滤器、BCrypt 密码。
- 同步策略：客户端 UUID 作主键 → push 幂等 upsert；`updated_at` 做 last-write-wins；pull 返回 `updatedAt > since` 的行（含软删 deleted=1），单用户双端场景够用。
- DTO 预留 `channel/code` 字段，将来换手机号验证码登录只改实现不动接口。
- 表结构走 Flyway `V1__init.sql`，`ddl-auto: validate` 保证实体与 SQL 一致。

## 如何解决的（踩坑记录）
1. **编译错误**：`BizException` 同时用了 `@AllArgsConstructor` 和手写同签名构造函数 → 删 Lombok 构造器保留手写（手写才能 `super(msg)`）；`GlobalExceptionHandler` 访问私有字段 → 改用 Lombok getter。
2. **数据库连接**：MySQL 8 caching_sha2 认证报 `Public Key Retrieval is not allowed` → JDBC URL 加 `allowPublicKeyRetrieval=true`。
3. **Schema 校验**：SQL 的 `TINYINT` 与实体 `int`（INTEGER）不符 → V1 改 `INT`，开发库无数据直接 `down -v` 重建卷。
4. **Repository 不注册**：把三个 Repo 写成接口内的嵌套接口，Spring Data 扫不到 → 拆成顶层 `TxRepo/AccountRepo/BudgetRepo`。
5. **HQL 实体名**：嵌套实体 `SyncEntities.TxRecord` 的限定名/简单名都解析失败 → `@Entity(name = "TxRecord")` 显式命名。
6. **测试脚本坑**：PowerShell 5.1 给 curl 传多行 JSON 会被拆坏 → `ConvertTo-Json -Compress` 写文件后 `curl -d @file`；`curl` 要加 `--noproxy "*"`（本机系统代理 8888 会劫持 localhost）。

## 最后结果（curl E2E，容器 shanji-db + shanji-app 运行中）
| 用例 | 结果 | 证据 |
|---|---|---|
| M5-01/M5-04 健康检查 | PASS | `GET /api/health` → `{"status":"UP",...}` |
| M5-02 注册 | PASS | 200 + token + expiresAt |
| 重复注册 | PASS | 409 用户名已存在 |
| 登录 / 错误密码 | PASS | 200+token / 401 |
| 无 token 访问同步 | PASS | 403 拒绝 |
| M5-03 push 3 笔 | PASS | accepted=3 |
| pull since=0 | PASS | 返回 3 笔 |
| LWW：新时间戳覆盖 | PASS | accepted=1，pull 验证 amount=99.9/merchant=A2 |
| LWW：旧时间戳忽略 | PASS | accepted=0 |

**运行方式**：`cd shanji-server && docker compose up --build -d`（MySQL 8.4 + 应用，端口 3306/8080，配置在 `.env`）。
**遗留**：无 token 返回 403（Spring 默认）而非 401，个人项目可接受；JWT 过期不做刷新；生产需改 `JWT_SECRET` 与密码。
