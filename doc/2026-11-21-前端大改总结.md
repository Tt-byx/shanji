# 2026-11-21 前端大改总结

## 用户的问题

大改一次前端，动手前先去 GitHub / 网络调研客户端页面交互设计，遵循以下规则：

1. 砍掉标语、提示文字和次要标签；如果一个页面非得靠这些才看得懂，那就去改布局；
2. 每个决定同时提升用户体验（UX）、开发者体验（DX）和智能体体验（AX），不能弄坏任何功能；
3. 页面要人性化提示，不要出现"返回 400"这种技术错误——实际是账号不符合规则时，提示必须说人话。

## 如何分析的

1. **调研先行**：派子代理在 GitHub / 网络上调研记账类 App 的交互与设计规范，产出结论存于 `doc/2026-11-21-记账App-UI重构设计研究总结.md`：
   - 错误提示放在字段附近，写"如何避免"，绝不暴露状态码 / 英文术语；
   - 空状态 = 单一 CTA 按钮，而不是一段指路文字；
   - 登录页不需要说明段落，密码框要有可见性开关；
   - 设置菜单去掉副标题，改成单行 + 右箭头；
   - AX：语义 contentDescription、布局稳定、一屏一个主行动。
2. **文案审计**：grep 全 `ui/` 目录，列出所有长说明、标语、placeholder、菜单副标题，逐一判断"删掉后页面是否还看得懂"——看得懂就删，看不懂就改布局。
3. **错误链路分析**：注册 400 事件的根因是客户端没有前置校验（用户名 < 3 位、密码 < 6 位），且服务端错误原样透传（HTTP 状态码、英文 validation message、Retrofit `HttpException` 的 "HTTP 401"）。解决思路是**单点映射**：所有错误统一过 `SyncManager.friendlyError()`，DX 上新增错误只改一处。

## 如何解决的

### 一、砍文案（UX：页面自解释）

| 页面 | 删除/修改 |
|---|---|
| LoginScreen | 删说明段落"登录后账本可云同步…"；label 简化为"用户名"/"密码"；密码加可见性开关 |
| ProfileScreen | MenuItem 去副标题（改单行+右箭头）；删底部标语"闪记 FlashNote…"、"数据保存在本机…"、应用锁/预算说明段；AI 设置示例段落改 placeholder |
| HomeScreen | 空状态从指路文字改为 **"还没有账单" + 「记一笔」按钮**（改布局，接线 MainActivity `onAdd`） |
| AccountsScreen | "总资产（N 个账户）"→"总资产"；删底部"点击账户可修改…" |
| CalendarScreen | 删"颜色越深表示当天花得越多…" |
| RecurringScreen | 删顶部生成规则说明；"商户 / 事项（如：房租）"→"商户 / 事项" |
| RecordSheet | 删 placeholder "这笔钱花在哪了"、"添加备注，如：下午茶 · 和小林"（label 已足够） |
| SearchScreen | 保留搜索 placeholder（输入框需要示例格式，属功能性的） |

**保留**：确认对话框的后果文案（"会覆盖当前全部账单，继续？"）、底部导航文字标签（AX 语义锚点）、E2E 断言锚点 label。

### 二、错误人话化（UX + DX + AX）

`SyncManager.friendlyError()` 单点映射，覆盖：

- **Retrofit `HttpException`（新发现的坑）**：优先读 errorBody 里服务端已有的人话 message；取不到按状态码兜底（401→"账号或密码不对，再检查一下"、409→已被注册、400→输入不符合要求、429→太频繁、5xx→服务器开小差）；英文 validation message（size/blank/must）翻译成"用户名至少 3 个字符"/"密码至少 6 位"；
- 网络层：DNS 失败→"连不上服务器，检查网络后重试"、超时→"连不上服务器，稍后再试"；
- 5xx 空 message→"服务器开了小差，稍后再试"。

`login/register/testConnection/syncNow` 全部走该函数；LoginScreen 提交前**就地校验**（空用户名 / <3 字符 / 密码 <6 位），错误显示在字段旁并置 `isError` 红框，焦点留在问题字段。

### 三、AX

- 密码框 trailingIcon `contentDescription` "显示密码"/"隐藏密码"；
- 首页空状态 CTA 一屏一个主行动；
- 底部导航保留文字标签。
