# 2026-11-22 真机卡顿性能优化总结

## 用户的问题

真机（红米 K70 / Android 16 / HyperOS 3.0.307）上运行有卡顿、掉帧的感觉，要求优化体验。

## 如何分析的

静态审查构建配置与数据流，找到 4 个叠加根因（K70 是旗舰 SoC，排除硬件因素）：

1. **一直交付 debug 包**：`app/build.gradle.kts` 里 release 未配签名且 `isMinifyEnabled=false`，构建管线（build.sh、历次交付）全部走 `assembleDebug`——无 R8 代码优化、debuggable、Compose 调试插桩，整体性能差一档；
2. **主线程 `runBlocking` 写库**（`Model.kt` TxStore）：`add/update/remove/clear/replaceAll` 全部 `runBlocking { dao.insert(...) }`——每次记账/删除都阻塞主线程等 SQLite 磁盘 IO，保存瞬间必掉帧；`seedDemo`（80 行入库）和 `migrateLegacyFile`（文件 IO）也跑在主线程（卡启动）；
3. **每次写库全量刷新**：`observeAll` 收到后 `txs.clear() + addAll()` 结构性变更，所有读 `txs` 的页面全部重组；
4. **统计计算无记忆化**：HomeScreen `Ledger.monthSummary/dailyGroups`、StatsScreen 五组统计、ProfileScreen `Ledger.summary` 都在**每次重组**时执行 O(n) 扫描——任何状态变化（滚动、输入、切页）都重跑。

## 如何解决的

### 1. 构建层（最大杠杆）
- `signingConfigs.release` **复用构建镜像里的固定 keystore**（`/root/.android/debug.keystore`）——与历史 debug 包同签名，可直接覆盖安装，无需卸载；
- release 开启 `isMinifyEnabled=true` + `isShrinkResources=true` + `proguard-android-optimize.txt`，新增 `proguard-rules.pro`（kotlinx-serialization serializer 保留、Retrofit/OkHttp/Room/Biometric 规则）；
- `build.sh` 与 README 切到 `assembleRelease`；versionCode 4→5、versionName 1.3→1.4。

### 2. 写库全部移出主线程（Model.kt）
- `add/update/remove/clear/replaceAll` → `scope.launch { dao.xxx }`（Dispatchers.IO），UI 即时反馈由 `observeAll` 流回刷；
- 首启一次性工作（文件迁移 + 演示数据 80 行入库）合入**同一 IO 协程顺序执行**（既不卡启动，也避免迁移/播种竞态）；
- 启动时周期账单补记（`RecurringScheduler.checkAndRun`，内含写库）移到后台 `Thread`，不拖慢首帧。

### 3. 统计记忆化（3 个热点页）
- `AppStore.version: MutableState<Int>`：`observeAll` 数据真正到达时 +1（唯一真相源，与 txs 更新同帧）；
- HomeScreen `summary/groups`、StatsScreen 五组统计、ProfileScreen `summary` 全部 `remember(range/ym, dataVersion)`——无关重组不再跑 O(n) 扫描。

## 最后结果

**构建**：`assembleRelease` BUILD SUCCESSFUL，**APK 从 19.4MB 降到 2.3MB**（R8+资源收缩），同签名覆盖安装 Success。

**E2E（MuMu + release 包，全部 PASS）**：

| 用例 | 结果 |
|---|---|
| 启动 + Room 数据加载（R8 下反序列化） | PASS |
| 记一笔 6.66 PerfTest 保存 → 异步写 → observe 回刷显示 | PASS |
| 统计页（remember 重算正确：11月总支出/上月总结） | PASS |
| AI 对话（kotlinx-serialization 在 R8 下序列化/反序列化） | PASS |
| 立即同步（Retrofit 全链路，上次同步 17:35） | PASS |
| 我的全菜单（外观/应用锁/预算设置/周期记账/AI 识别设置/立即同步） | PASS |
| 账户（总资产）、外观切换（深色→恢复跟随系统） | PASS |

**效果预期**（静态优化依据）：
- 记账/删除保存瞬间不再有主线程磁盘 IO 阻塞（掉帧主源）；
- 滚动/切页等无关重组不再触发 O(n) 统计重算；
- R8 优化包体积 -88%，运行时代码路径更优；
- 启动不再被 80 行种子数据/文件迁移卡住。

**给用户的验证指引**：把 `apk/ShanJi-v1.2-debug.apk`（现为 release 包，文件名未变）装到 K70 直接覆盖安装，重点感受：记账保存瞬间、首页滚动、Tab 切换。若仍有个别场景掉帧，可开「开发者选项 → GPU 剖析」或告知具体操作路径，再做针对性优化（如 LazyColumn 深度、图表绘制）。

**遗留**：桌面小组件每次写库都 `WidgetUpdater.update`（RemoteViews 主线程 Binder），低频可接受未动；`exportJson` 主线程编码（数据量小 <10ms）未动。
