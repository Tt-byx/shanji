# 应用锁/语音删除、主页加号与 DeepSeek 聊天样式总结（2026-11-22）

## 用户的问题
1. **删掉应用锁**——鸡肋，手机系统自带应用锁；
2. **记账页麦克风点不了语音输入**——修得麻烦就直接删掉该功能；
3. **主页记账图标**由照相机改成加号（添加的意思）；
4. **AI 回复不要气泡**（猜测气泡会等全文才定宽、影响流水输出），参考 `.screenshots/deepseek的聊天截图.jpg`；用户消息气泡"文字多长气泡多长"贴合内容；
5. 用 GitHub 的 **REA 逆向项目**分析用户提供的 `money\DeepSeek.apk`，看别人怎么做的。

## 如何分析的
1. **应用锁**：入口在 MainActivity（LockScreen 守卫）+ 我的页菜单/对话框 + LockManager/LockScreen 两个文件 + biometric 依赖——全链路删除；fragment-ktx 保留（MainActivity 基类 FragmentActivity 需要）。
2. **语音**：`VoiceInput.kt` 用系统 `SpeechRecognizer`——该服务依赖 Google 识别组件，**红米 K70 国行 ROM 无 GMS 必然不可用**，修复需接云端 ASR（成本高）→ 按用户预授权直接删除：VoiceInput.kt、记账弹层麦克风按钮、RECORD_AUDIO 权限、相关导入；**AiRecognizer（截图 AI 识别）是另一功能，保留**。
3. **图标**：HomeScreen 头部 `PhotoCamera("截屏记账")` 按钮实际行为与 onAdd 相同（都打开记一笔弹层）→ 换成 `Add("记一笔")` 主题蓝，删掉冗余 onCapture 参数。
4. **聊天样式**：对照 DeepSeek 截图——AI 回复=无气泡、全宽、左对齐纯文本（Markdown 照常渲染）；用户消息=浅蓝气泡贴合文字（`widthIn(max=300dp)` 限宽换行）整体靠右。打字机节奏在气泡内自带（`LaunchedEffect` 每33ms推进2~5字），**与有无气泡无关**——原"等全文定宽"的猜测在我们的实现里不成立（原气泡本来就是固定82%宽），但无气泡样式更贴近 DeepSeek、也更利于流水观感，照改。
5. **REA 逆向**（工具链：`npx rea-agents`（rea@6.8.0）+ 本机 apktool 2.11.1（供 REA 的 decode-android-resources 用）+ jadx 1.5.1 反编译）：
   - `rea doctor/analyze`：APK 属 archive，原生分析需要 Ghidra/Hopper/IDA（未装）；JS 路径不适用——**DeepSeek 不是 React Native**（`assets/vendors.js` 只是 WebView 的 mermaid webpack chunk）；
   - `rea decode-android-resources` 成功：**com.deepseek.chat v2.6.2、Jetpack Compose 原生应用、targetSdk36、MainActivity `windowSoftInputMode=adjustResize`**（与我们同款键盘策略）、含 RECORD_AUDIO/前台麦克风服务（他们的语音走自研服务）；
   - jadx 反编译 14152 个 Java 文件后按协议特征取证：请求参数 **`"stream"`**、`"delta"` 解析、埋点字段 **`sse_transaction_uuid` / `sse_time_elapsed` / `stream_scenario` / `sse_toast`** → **DeepSeek 用的就是 SSE 流式（与我们同方案）**；未发现任何 typewriter/打字机类——他们不加显示节奏，靠模型速度自然流出；我们的打字机是针对 `deepseek-flash` 过快（0.9秒答完）的必要补充。

## 如何解决的
按上述分析执行五项修改：MainActivity/ProfileScreen/Manifest/build.gradle 删应用锁与语音（删除 LockScreen.kt、LockManager.kt、VoiceInput.kt 三个文件、biometric 依赖、RECORD_AUDIO 权限）；HomeScreen 图标换加号；ChatBubble 重构为 DeepSeek 样式（AI 无气泡 MarkdownText 全宽 + 用户 widthIn 贴合气泡 + ▌光标也改无气泡）；版本升 versionCode 8 / v1.7（build.sh、README 同步）；REA/jadx/DeepSeek.apk 全部 gitignore 不入库。

## 最后结果（E2E 实测，MuMu + v1.7）
- **主页**：头部为蓝色加号（截图确认），点击打开记一笔弹层 PASS；
- **记账弹层**：无语音入口、一句话 AI 解析（AI 解析按钮）保留 PASS（代码 grep 无 Mic/VoiceInput 残留）；
- **我的页**：菜单无"应用锁"（外观/预算设置/周期记账…）PASS；
- **聊天**：截图确认 AI 回复无气泡全宽纯文本、用户气泡贴合文字靠右、加粗/列表 Markdown 正常、打字机与回复到达正常 PASS；
- **回归**：五 tab 正常；构建 1.8MB（删功能后更小）。
- 逆向产物（rea/、rea-tools/、DeepSeek.apk）均已 gitignore。

**遗留**：① DeepSeek 原生代码混淆（单字母类名），更深层的流式 UI 绑定需 Ghidra 级分析，当前证据（SSE 协议 + Compose + 无打字机）已足够支撑我们的实现选型；② 若以后想恢复语音，建议接云端 ASR（如阿里/讯飞）而非系统 SpeechRecognizer。
