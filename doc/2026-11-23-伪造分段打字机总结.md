# 伪造分段打字机总结（2026-11-23）

## 用户的问题
打字机版本在真机上还是"一下子蹦出整段"。用户怀疑是回复太短、一个 chunk 就到齐了；提出改造思路：**不硬做真流式了，本地伪造流式——一段一段往外蹦的打字机感觉**（显示节奏与网络解耦）。

## 如何分析的
1. **复盘上一版（v1.7 逐字打字机）为何在真机失效**，定位三个叠加原因：
   - **act 路径（查账/记账两轮对话）完成时把打字中的气泡删掉、用全文重建新气泡**——新气泡按全文初始化，一整段直接上屏（用户测试的查账问题全走这条路，体感必然是"一下子蹦"）；
   - 逐字节奏 60~150 字/秒：60 字短回复 0.4 秒就打完，肉眼≈瞬间；
   - 气泡内 `remember` 状态在滚动离开视口后重建时按当时全文初始化，长回复滚动会丢进度直接全文。
2. **用户的"伪造"思路与我们的架构本来一致**（items 存全文、显示层控节奏），核心是把节奏器改可靠 + 改成"段"为单位：
   - 切段器 `segmentEnds()`：句末标点（。！？；…!?; 换行，含其后右引号右括号）后切一段，英文句点仅句尾位置切（避开 3.14），超 40 字无标点强制切一段兜底；
   - 进度状态 `typedSegs`（bubbleId→已蹦段数）**提升到页面级 SnapshotStateMap**——滚动/重组/任何重建都不丢进度；
   - 初始值规则：新气泡创建时空文本→0 段从头蹦；历史消息创建即全文→段数=全部直接显示（不重播）；
   - 节奏：≤3段 300ms/段、≤10段 200ms、≤18段 140ms、更多 70ms——**短回复也保证有肉眼可见的节奏**，长回复加速防拖沓；
   - act 路径改为**绝不删气泡重建**，首轮文本留在原气泡蹦完，二轮另起新气泡继续蹦。
3. **E2E 采样的"假失败"排查**：密集采样只测到2步，但 logcat 埋点（bubble init / tick N/total / idx=-1 告警）给出完整时序——**网络 0.1 秒整段到齐后，显示仍按 140ms/段 × 14 段 = 1.8 秒逐段蹦出**（00:01:48.844→50.669，每段间隔精确140ms）。采样只有2步是 uiautomator dump 每次约2秒 > 打字总时长1.8秒的工具限制，非功能问题。

## 如何解决的
按上述方案改 ChatScreen：新增 `segmentEnds()` 切段器；`typedSegs` 页面级状态；ChatBubble 重构为分段节拍器（含 ▌ 光标占位态）；act 路径去掉删+重建；openConversation 清进度；埋点日志（init/tick/idx 告警）保留便于真机取证；版本升 versionCode 9 / v1.8（build.sh、README 同步）。

## 最后结果（logcat 铁证，MuMu + v1.8）
```
00:01:47.158 bubble init id=b41717 textLen=0 segs=0      ← 新气泡从0开始
00:01:48.801 chunk#1 n=138（整段一次性到达，网络侧无关）     ← 你说的"一条chunk到齐"
00:01:48.844 tick 1/14 → 每140ms一段 →
00:01:50.669 tick 14/14                                    ← 1.8秒逐段蹦完
```
- 伪造分段打字机 PASS：无论网络多快，显示按句子一段一段蹦（短回复300ms/段，长回复最快70ms/段）；
- 历史消息按全文初始化不重播 PASS（init 日志：textLen=874 segs=58 直接显示）；
- act 查账路径不再删气泡重建（全文直出的根源已除）；
- 打字进度状态在页面级，滚动/重组不丢。

**遗留**：① 节奏手感（段间隔300/200/140/70ms 四档）真机确认，想更慢/更快改 ChatBubble 里 `delay(when{...})` 一行；② SHANJI 埋点日志（bubble init / tick）保留在 release 里，真机异常可 `adb logcat -s SHANJI` 取证。
