# 聊天键盘空隙、流式输出与 Markdown 渲染修复总结（2026-11-22）

## 用户的问题
真机（红米 K70 / Android 16 / HyperOS）上发现 4 个问题（附截图 `.screenshots/微信图片_20261122185506_56_339.jpg`）：
1. AI 对话页输入框和键盘之间有很大一段空格；
2. AI 的输出不是流式输出（一整段整段蹦）；
3. AI 会先回答一句、再回答一句——用户觉得这样拟人化，**希望保留**；
4. AI 回复带 Markdown 符号（`**`、代码围栏等），两个方案二选一：禁止 AI 输出 MD / 让 App 渲染 Markdown——**用户选第二个（渲染 Markdown）**。

## 如何分析的
1. **键盘空隙**：读 ChatScreen/MainActivity/Manifest——`targetSdk=36`，Android 15+ 强制 edge-to-edge 后 `windowSoftInputMode=adjustResize` 不再缩窗口，只有 `WindowInsets.ime` 变化。ChatScreen 自己 `imePadding()` 正确抬升了输入框，但外层 Scaffold 的**底部导航栏高度 + contentWindowInsets 底部空间是固定预留**，键盘弹出后这段空间没被收掉 → 输入框与键盘之间正好空出「底栏+导航栏」一段（与截图空隙吻合）。模拟器验证：MuMu 的 IME 不下发 insets（`mInputShown=true` 但布局无反应），空隙只能真机确认，修复针对该行为是确定性的。
2. **非流式**：读 AiClient——`chatStream` 用 `readUtf8Line()` **按行读**，模型回复里换行很少，客户端要等到 `\n` 才把攒着的文本抛给 UI → 段落级才显示一次，看起来就是"不是流式"；换行处又恰好分句 → 造成"先一句再一句"的观感。服务端（AiService/AiController）本来就是逐 delta 写+flush 的，问题纯在客户端读法。
3. **两句回复**：`send()` 里 queryTx 动作两轮对话（先答一句 → 本地查账 → 再补一段）是设计行为，用户喜欢 → **不动**。
4. **Markdown**：用户选渲染方案。评估过三方库（mikepenz multiplatform-markdown-renderer，最新 0.46.0），但 Kotlin 2.0.21 / Compose BOM 1.7 的版本兼容与 R8 风险不可控 → **手写轻量渲染器**（零依赖、可控、流式半截文本安全）。

## 如何解决的
1. **键盘空隙**（MainActivity.kt）：读 `WindowInsets.ime` 判断键盘是否弹出——弹出时收起底部导航栏、把 Scaffold contentWindowInsets 底部清零（保留状态栏顶部 inset），子页面的 `imePadding()` 从此精确贴到键盘顶；顺手给 LoginScreen 根 Column 也加了 `imePadding()`（同因，密码框真机会被键盘盖住）。
2. **真流式**（AiClient.kt）：按行读改为 `InputStreamReader` **按网络 chunk 即读即抛**（自带 UTF-8 跨包解码）；首行 `#ACT#` 判定保留（攒够 5 字符或等到换行）；模型自己的换行语义还原。服务端零改动。
3. **Markdown 渲染**（新建 ui/Markdown.kt，约 280 行）：按行分块 + 行内正则，支持标题 / **加粗** / *斜体* / `行内代码` / 围栏代码块 / 无序与有序列表 / 引用 / 分割线 / 表格（带表头分隔线）/ 链接；未闭合的 `**`/``` 按普通文本或未关代码块渲染，流式增量安全。ChatBubble 里 AI 气泡换用 `MarkdownText`，用户气泡保持纯文本。
4. 版本升到 versionCode 6 / v1.5，产物改名 `ShanJi-v1.5-release.apk`（build.sh + README 同步）。

## 最后结果（MuMu E2E）
- **流式 PASS**：发送问题后 0.7s dump=599 字符 → 2.0s=722 字符 → 之后不变，文本分批到达（旧版是最后一次性出现）；
- **Markdown PASS**：列表（`•` 与条目是独立节点）、**加粗标题**（"本月账本：¥1,713.24 已经花掉了"）、**表格**（分类/金额/占比 表头 + 分隔线 + 数据行）均正确渲染，回复中无原始 `**` 残留（用户气泡里的 `**` 是提问原文，按设计保持纯文本）；
- **回归 PASS**：明细/统计/账户/我的四 tab 正常，Room 数据完整；
- **键盘空隙**：MuMu IME 不下发 insets 无法截图验证（`mInputShown=true` 但布局不动），修复基于 Android 15+ edge-to-edge 的确定性分析，**待真机确认**。

**遗留**：① 真机装 v1.5 后重点看输入框是否贴键盘、底部导航栏是否随键盘收起；② 手写 Markdown 渲染器未覆盖嵌套列表/图片/脚注（聊天场景用不到），发现渲染异常的文本发我即可补。
