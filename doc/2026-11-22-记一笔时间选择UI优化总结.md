# 2026-11-22 记一笔时间选择 UI 优化总结

## 用户的问题

记一笔弹层里选时间的 UI 很丑，想优化；老规矩——先去网上找一圈 UI 设计参考，再决定怎么做。

## 如何分析的

### 1. 现状问题（丑的根源）

旧实现是三段式两连击：
- readOnly 输入框显示 `2026年11月22日 01:03` + 一个 12sp 的"修改"小字按钮；
- 点"修改" → 系统 `DatePickerDialog` → 点"下一步" → 系统 `TimePicker` 对话框 → 点"确定"；
- **两个独立对话框、三步操作、按钮文案弱**（"下一步"语义不明），日期与时间割裂在两个弹窗里。

### 2. 网上调研（两轮检索）

- **Picker 形态适用场景**（Apple HIG / Setproduct）：滚轮 picker 适合近端单一时间快速选；日历 picker 适合日期概念清晰、补账跨天；
- **最佳实践**（Digital Thrive）：渐进披露（Progressive disclosure）、智能默认（Smart defaults）、清晰视觉反馈；
- **记账类产品实例**：标签记账的更新日志明确写了「「昨天 / 今天」快速改日期」；随手记有"记账日历快速跨天补账"；
- **Material3 现状**：Compose M3 提供 `DatePicker`/`TimePicker`/`TimePickerDialog` 组件，可自由组合。

**结论**：记账场景 90% 是"今天/昨天"，应该让高频路径一步到位（快捷 chips），低频的精确日期+时分合并为**一个**弹层一次确定（渐进披露 + 减步骤），而不是两个系统对话框接力。

### 3. 决定的方案

```
时间
[前天] [昨天] [今天]        🕐 16:21   ← 点右侧值
```
- **快捷 chips（前天/昨天/今天）**：点击直接切换日期、保留当前时分——0 弹层一步完成，选中态 Primary 高亮；
- **右侧时间值胶囊**（时钟图标 + 时间）：非今天时显示"昨天 16:21"/"11月15日 16:21"前缀，信息自明；
- **点时间值 → 单个 ModalBottomSheet**：日历（DatePicker）+ 时分盘（TimePicker）同屏（可滚动），取消/确定**一次应用**——替代旧的 日期→下一步→时分 两连击。

## 如何解决的

改动仅 `shanji-android/ui/RecordSheet.kt`：
1. 状态收敛：`showDatePicker/showTimePicker/pendingDate` 三个状态 → `showTimeSheet` 一个；
2. 时间行 UI 重写：标签"时间"（保留 13sp 标签风格与其它字段一致）+ 快捷 chips + 时间值胶囊（`Icons.Filled.Schedule` 时钟图标）；
3. 尾部两段对话框代码删除，替换为单页 `ModalBottomSheet`（`verticalScroll` 容纳日历+时分盘，确定时 `dateState × timeState` 一次性合成 `dateTime`）；
4. 快捷日期切换保留原时分：`date.atTime(dateTime.hour, dateTime.minute)`（补账场景改日期不动钟点）。
